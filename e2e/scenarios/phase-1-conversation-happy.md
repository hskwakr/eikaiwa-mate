# Phase 1 — 統合 happy path: 英語音声会話 + 双方向字幕

> シナリオ markdown の書き方・観測子の粒度・superset の定義は
> [docs/testing/e2e.md](../../docs/testing/e2e.md) を参照。横断マップ(シナリオ一覧 /
> エラーコード網羅 / カバレッジ)は [README.md](./README.md) を参照。

## 受け入れ条件

spec.md のコア要件 3 つ + plan.md Phase 1 done 条件(両者の出典は本リポジトリ管理外。
[README.md](./README.md) の「出典について」参照):

- 自分の英語発話を AI に送れる
- AI が英語音声で返答する
- 自分と AI 双方の発話が画面に字幕として表示される
- ブラウザで動作する(ローカル動作で可)

本シナリオは、これら 4 条件を 1 つの会話セッション内で連続的に観測する。

## 前提

- ephemeral token 発行 API (`/api/session`) は成功レスポンスを返す
- マイク許可ダイアログは「許可」される
- WebRTC コネクションは成功する
- AI 側は user の英語入力に対し英語で 1〜2 文返す
- ブラウザは Chromium 系を想定(モバイル viewport も含む)

> Realtime API / WebRTC / マイク入力の詳細は e2e 実装側でモック / fake 化する
> (fake adapter + Chromium fake media stack)。本シナリオ markdown は「ユーザーが
> 観測する事象」のみを書く。

## ユーザー行動

1. アプリの top page を開く
2. セッション開始ボタン(接続を開始するボタン)を押す
3. マイク許可ダイアログで「許可」を選ぶ
4. マイクが有効になった状態で、英語で 1 文話す(例: "Hello, how are you today?")
5. AI の返答音声が再生されるのを待つ
6. 続けてもう一度英語で話す(例: "What did you do yesterday?")
7. AI の 2 度目の返答を待つ
8. セッション終了ボタン(接続を切るボタン)を押す

## 観測すべき事項

### セッション開始フロー

- ヘッダの状態バッジが 初期(未接続) → 接続処理中 → 待機 の順に遷移する
  - 表示文字列は `STATE_LABEL`(`StateBadge.tsx`)参照。`SessionState` の
    `idle` → `connecting` → `listening` に対応する。文言自体は実装裁量
- 状態バッジは `aria-live="polite"` を持ち、スクリーンリーダーに状態変化を通知する
- マイクトグルボタンは「未接続時 disabled」「接続後 enabled」になる
- エラー領域 (`role="alert"`) は表示されない

### 字幕表示(ユーザー発話)

- ユーザーが話し始めると、ユーザー発話の字幕バブルが画面に追加される
- 発話途中(interim transcript)はバブル内に表示され、確定前であることが視覚的に
  分かる形式で出る(italic / 不透明度低下 等の方法は実装の裁量)
- 発話が完了すると、同じバブルの内容が確定形(non-italic / 不透明度通常)に変わる

### 字幕表示(AI 発話)

- AI が返答を始めると、AI 発話の字幕バブルが追加される(ユーザーのバブルとは
  視覚的に区別できる: 配置 / 配色 等の方法は実装の裁量)
- 返答が完了すると AI バブルも確定形になる
- 状態バッジは AI 発話中 AI 発話状態、発話完了後 待機 に戻る
  - `SessionState` の `speaking` → `listening`。表示文字列は `STATE_LABEL` 参照

> ⚠ **superset(PR2 spec.ts カバー外)**: 「字幕の文字とほぼ同期して AI の音声が
> 再生される」は受け入れ仕様としては必須だが、e2e は adapter no-op + Chromium fake
> media stack で実音声を流さないため spec.ts では assert しない。仕様として残す。
> 詳細は [docs/testing/e2e.md](../../docs/testing/e2e.md) の superset 定義を参照。

### 2 ターン目以降

- 2 ターン目以降も同様に、ユーザー / AI それぞれのバブルが時系列順に積み上がる
- スクロールは最新の発話が見える位置に追随する(モバイル想定で重要)

### セッション終了

- 終了ボタン押下後、状態バッジは 初期(未接続)に戻る(`SessionState` の `idle`)
- マイクトグルボタンは再度 disabled に戻る
- 過去の字幕バブルは画面に残る(切断では字幕をクリアしない。永続化はせず、次に接続を
  開始すると字幕表示はリセットされる)

## 失敗とみなすケース

- 状態バッジが想定外の順序で遷移する(例: 接続処理中(`connecting`)を飛ばして
  初期から待機へ遷移する)
- ユーザー発話の interim transcript が「確定形と同じ見た目」で出てしまい、確定状態と
  区別できない
- AI バブルとユーザーバブルが視覚的に区別できない
- エラー領域 (`role="alert"`) が happy path で表示される
- セッション終了後に状態バッジが 初期(`idle`)以外で残る
- マイクトグルボタンの enabled / disabled 状態が「接続状態」と一致しない
