# Phase 1 — token 取得失敗経路

> シナリオ markdown の書き方・観測子の粒度・superset の定義は
> [docs/testing/e2e.md](../../docs/testing/e2e.md) を参照。横断マップ(シナリオ一覧 /
> エラーコード網羅 / カバレッジ)は [README.md](./README.md) を参照。

## 受け入れ条件

Realtime API への接続は ephemeral token を `/api/session` 経由で取得する必要がある
(OpenAI API key をブラウザに露出させないため)。token 取得が失敗した場合(API key
未設定 / バックエンドが落ちている / ネットワーク不調 等)でも、アプリは:

- 何が起きたかをユーザーに明示する
- マイク許可ダイアログを出さない(意味なくユーザーを煩わせない)
- アプリ全体がフリーズしない(再試行可能な状態に戻る)

を満たす必要がある。本シナリオは token 取得失敗時のエラー UX を観測する。

## 前提

- ephemeral token 発行 API (`/api/session`) が成功レスポンスを返さない
  - HTTP 4xx / 5xx
  - レスポンス JSON が期待形式と異なる(token 値が含まれない)
  - ネットワーク不達 (fetch reject)
  - 上記いずれの経路でも、ユーザー観測としては「セッション開始が成立しない」結果になる
- WebRTC コネクション確立より前で失敗するため、マイク許可ダイアログは出ない

> e2e 実装では `page.route()` で `/api/session` への POST を握り、上記いずれかの失敗
> レスポンスを返す。

## ユーザー行動

1. アプリの top page を開く
2. セッション開始ボタン(接続を開始するボタン)を押す
3. (マイク許可ダイアログは出ない、ことを観測する)
4. エラー表示を読む
5. もう一度セッション開始ボタンを押す(再試行できることを確認する)

## 観測すべき事項

### マイク許可ダイアログが出ないこと

- token 取得失敗 → ブラウザの getUserMedia は呼び出されない
- マイク許可プロンプトは出ない(出てしまうとユーザー混乱の原因)

### エラー UI の表示

- エラー領域 (`role="alert"`) が表示される
- エラー領域内にエラーコード `token_fetch_failed` が表示される
  (`RealtimeErrorCode` 型由来の安定識別子。uppercase / font-mono 等の見せ方は
  実装の裁量だが、文字列 `token_fetch_failed` 自体は exact で観測できる)
- エラーコードとは別の要素に「ユーザー向けの説明文」(`RealtimeError.message`)が
  表示される(文面は実装裁量)

### 状態バッジ

- 状態バッジは 接続処理中 を経て エラー状態 に遷移する
  (`SessionState` の `connecting` → `error`。表示文字列は `STATE_LABEL` 参照)
- 状態バッジは `aria-live="polite"` を持ち、変化がスクリーンリーダーに通知される

### コントロールの状態

- マイクトグルボタンは disabled になる(接続未確立のため)
- セッション開始ボタンは再度押せる状態に戻る(disabled で固まらない)
- アプリ全体がフリーズせず、リロードなしで再試行できる

### 字幕

- 字幕領域には新しいバブルは追加されない(発話以前の段階で失敗したため)
- 接続を開始するたびに字幕表示は空にリセットされる現挙動。エラー後に再試行を押すと、
  前のターンが残っていてもクリアされる(接続開始の操作そのもので字幕がリセットされる)

## 失敗とみなすケース

- マイク許可ダイアログが出てしまう(getUserMedia を呼んでしまった)
- エラー領域 (`role="alert"`) が表示されない
- エラーコード `token_fetch_failed` が観測できない
- 状態バッジが エラー状態(`error`)に遷移せず 接続処理中(`connecting`)のまま固まる
- セッション開始ボタンが disabled で固まり、再試行できない
- 別エラーコード(例: `connection_failed`)に化けて表示される
  (どの段階で失敗したかが伝わらなくなる)
