> エラーコード網羅 / カバレッジ)は [README.md](./README.md) を参照。

## 受け入れ条件

spec.md「マイクで自分の英語を AI に送る」ためにはブラウザのマイク許可が必須。
ユーザーが許可ダイアログで「拒否」を選んだ場合でも、アプリは:

- 何が起きたかをユーザーに明示する
- アプリ全体がフリーズしない(再試行可能な状態に戻る)
- ブラウザの権限ダイアログを再度開く操作を妨げない

を満たす必要がある。本シナリオはマイク権限拒否時のエラー UX を観測する。

## 前提

- ephemeral token 発行 API (`/api/session`) は成功レスポンスを返す
- マイク許可ダイアログでユーザーは「拒否」を選ぶ
- WebRTC コネクション確立より前に getUserMedia の denied が返る

> e2e 実装では Chromium fake media stack のマイク権限を明示的に拒否する設定で実行する。

## ユーザー行動

1. アプリの top page を開く
2. セッション開始ボタン(接続を開始するボタン)を押す
3. マイク許可ダイアログで「拒否」を選ぶ
4. エラー表示を読む
5. もう一度セッション開始ボタンを押す(再試行できることを確認する)

## 観測すべき事項

### エラー UI の表示

- エラー領域 (`role="alert"`) が表示される
- エラー領域内にエラーコード `mic_permission_denied` が表示される
  (`RealtimeErrorCode` 型由来の安定識別子。uppercase / font-mono 等の見せ方は
  実装の裁量だが、文字列 `mic_permission_denied` 自体は exact で観測できる)
- エラーコードとは別の要素に「ユーザー向けの説明文」(`RealtimeError.message`)が
  表示される(例: 何が起きたか / どう復旧するか の人間語メッセージ。文面は実装裁量)

### 状態バッジ

- 状態バッジは エラー状態 に遷移する(`SessionState` の `error`。視覚上、平常時と
  区別できる配色である。表示文字列は `STATE_LABEL` 参照)
- 状態バッジは `aria-live="polite"` を持ち、変化がスクリーンリーダーに通知される

### コントロールの状態

- マイクトグルボタンは disabled になる(接続未確立のため)
- セッション開始ボタンは再度押せる状態に戻る(disabled で固まらない)
- アプリ全体がフリーズせず、リロードなしで再試行できる

### 字幕

- 字幕領域には新しいバブルは追加されない(発話できなかったため)
- 接続を開始するたびに字幕表示は空にリセットされる現挙動。エラー後に再試行を押すと、
  前のターンが残っていてもクリアされる(接続開始の操作そのもので字幕がリセットされる)

## 失敗とみなすケース

- エラー領域 (`role="alert"`) が表示されない
- エラーコード `mic_permission_denied` が観測できない
- 状態バッジが エラー状態(`error`)に遷移せず 初期 / 接続処理中 のまま留まる
- セッション開始ボタンが disabled で固まり、再試行できない
- マイクトグルボタンが接続未確立にも関わらず enabled で残る
- happy path 用の字幕バブルが空のまま追加される
